## CI 第三轮修复（仍属 1.8.9，未发布轮次）：php-lint 深层语法错误

上一轮 1.8.9 初步修复（performance 双反斜杠、删 PrototypeTest、bootstrap、phpcs、bump）被提交后，CI 的 `php -l` 在 `includes/modules/core/classes/class-wpca-core.php` 报新错 `Namespace declaration statement has to be the very first statement`——此前被 performance-ajax 的 abort 掩盖，modules/ 从未被完整 lint 过。

- 根因：`modules/` 下 12 个类文件在 `namespace` 声明**之前**写了 `require_once __DIR__ . '/...';` 依赖加载（modules 重构时引入的普遍模式）。PHP 要求 namespace 必须是首个语句（除 declare/注释）。
- 修复：脚本把每个文件 namespace 前的 `require/include` 整体移至 `namespace` 之后（保留原始 CRLF/LF 行尾，避免 diff 膨胀）。涉及 `modules/admin/classes/*`(7)、`modules/admin/settings/*`(3)、`modules/core/classes/*`(2)。
- 全仓库搜 `^function\s+\\`（全限定 `function \wp_...() {}` 非法声明）= 0 结果：确认主文件/performance 删除 stub 后已无残留；modules 文件的 "Declare WordPress functions for IDE compatibility" stub 用的是合法形式（`function wpca_get_settings() {}` 无反斜杠），语法合法、不阻塞 lint，本轮未删（避免扩大改动面）。
- 同步上述 12 个 modules 文件 + performance-ajax.php 头注释 `@version` → 1.8.9（遵守版本同步规则）。
- CHANGELOG 1.8.9 节补充 modules 命名空间修复条目。版本保持 1.8.9（同一未发布修复轮次，不二次 bump）。

## CI 第四轮修复（仍属 1.8.9）：trait 常量 PHP 版本不兼容

core.php namespace 修复提交后，CI `php -l` 继续扫描暴露新错：`class-wpca-error-levels.php` 第 28 行 `trait Error_Levels` 内 `const LOG_LEVELS`（PHP < 8.2 禁止 trait 常量，WP 插件需兼容 7.4+），CI PHP 版本较低 fatal。此前被前一轮 namespace 错误 abort 掩盖。

- 修复：trait 内 `const LOG_LEVELS = array(...)` → `public static $LOG_LEVELS = array(...)`（向后兼容 PHP 7.4）。使用类 `class-wpca-error-config.php`（`use Error_Levels;`）的 4 处 `self::LOG_LEVELS` → `self::$LOG_LEVELS`。
- 全仓库仅 1 个 trait 文件（error-levels），搜 `enum`/`readonly` 为 0，无其它 8.1/8.2 不兼容语法。
- `includes/class-wpca-error-handler.php` 的 `const LOG_LEVELS` 是其自身类内常量（PHP<8.2 合法），未改动。
- 同步 error-levels/error-config 头注释 `@version` → 1.8.9。版本保持 1.8.9（同一未发布 CI 修复轮次）。

## CI 第五轮修复（仍属 1.8.9）：主文件 array/isset 语言结构误用

error-levels/config 提交后，CI `php -l` 继续扫描暴露新错：`wp-clean-admin.php` 第 143 行起把 `array()` 语言结构误写成 `\array(`（带 `\` 命名空间前缀），PHP 将其当作**函数调用**，而函数参数中不能出现 `'key' => value` 数组语法 → 第 144 行 `syntax error, unexpected token "=>", expecting ")"`。此前被前序文件 abort 掩盖。

- 修复：全文件 10 处 `\array(` → `array()`（120/143/144/149/154/158/164/174/175/221）。其中 174/175/120/221 虽 lint 不报（`php -l` 只看语法），但运行期会 fatal（Call to undefined function array()），一并修。
- 同类型：`\isset(` 也是语言结构，第 123 行误加 `\` 前缀（运行期 fatal），改为 `isset()`。
- 全仓库搜 `\array(`/`\isset(`/`\empty(`/`\list(`/`\eval(` 语言结构误用，仅主文件有，已清除。
- 主文件 `Version:`/`WPCA_VERSION` 已 1.8.9，保持。
