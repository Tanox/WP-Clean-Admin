# 临时文件管理规范

> **适用基线**：1.9.18　|　**更新日期**：2026-11-22　|　**状态**：快速参考
> 生效范围：本仓库全部目录（含根目录、`wpcleanadmin/`、`docs/`、`prototype/`、`openspec/` 等）。开发规范以根 [`CONTRIBUTING.md`](../CONTRIBUTING.md) 为准。
> 违反本规范产生的文件不得提交入库。

## 1. 核心规则

1. **禁止在仓库根目录（及任何源码目录）直接创建临时文件**，包括但不限于：
   - 脚本中间产物（诊断脚本、一次性 `.mjs`/`.ps1`/`.php`/`.sh` 探针）
   - 日志、缓存、下载文件、测试输出、报告草稿
2. **所有临时文件统一存放于仓库根目录的 `tmp/` 子目录**（本仓库唯一约定的临时目录）。
3. `tmp/` 目录：
   - **可自动创建**：任何脚本/命令写入前必须先确保目录存在（见 §3）；
   - **易于清理**：整目录可随时删除重建，删除不影响任何功能（`tmp/` 内不存放任何需要保留的产物）；
   - **被版本控制忽略**：已在 `.gitignore` 中声明 `/tmp/`，其中的任何文件（含 `.gitkeep`）都不会进入版本库。

## 2. 命名与存放约定

- 临时文件名建议携带日期与用途后缀，便于定位与批量清理，例如：
  `tmp/scan-report-20261122.mjs`、`tmp/git-check-20261122.log`。
- 诊断类一次性脚本（如排查用的 `_*.mjs`）一律放入 `tmp/`；历史根目录遗留的此类文件已全部迁出，不得再新建于根目录。
- 需要跨会话保留的正式产物（审计报告、设计文档等）应放入 `docs/` 等正式目录并提交版本控制，不属于临时文件。

## 3. 脚本中的引用方式（避免路径硬编码散落）

所有脚本与代码**必须通过统一变量/常量指向 `tmp/`**，不得在多处手写相对路径：

**PowerShell：**

```powershell
$TmpDir = Join-Path $PSScriptRoot 'tmp'
New-Item -ItemType Directory -Force -Path $TmpDir | Out-Null   # 自动创建
Out-File -FilePath (Join-Path $TmpDir 'my-output.log')
```

**PHP（命令行工具脚本）：**

```php
$tmp_dir = __DIR__ . '/tmp';
if ( ! is_dir( $tmp_dir ) ) {
    mkdir( $tmp_dir, 0755, true ); // 自动创建
}
file_put_contents( $tmp_dir . '/my-output.log', $data );
```

**Node.js（诊断脚本）：**

```js
import { mkdirSync } from 'node:fs';
mkdirSync('tmp', { recursive: true }); // 相对仓库根，自动创建
```

**WordPress 运行时代码**（插件内需要写临时/缓存文件时）不使用仓库根 `tmp/`，而使用
`wp_upload_dir()` 下的插件专属子目录（如 `uploads/wpca-cache/`），参见
`includes/modules/utilities/classes/class-wpca-cache-file-tasks.php` 的既有实现；仓库根
`tmp/` 仅服务于**开发/审计期的本机脚本**，不参与线上运行时。

## 4. 清理方式

- 手动清理（整目录删除重建即可）：

  ```powershell
  Remove-Item -Recurse -Force .\tmp; New-Item -ItemType Directory -Force .\tmp | Out-Null
  ```

- 建议在每次审计/诊断批次结束后随手清理；`tmp/` 不进版本库，清理无需提交。
